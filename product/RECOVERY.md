## 이번에 보완한 항목

1. **초기 상태 제안:** 매출 단계의 1인 창업자가 음수 현금을 제안받는 문제를 수정했습니다. 6개 단계 × 3개 팀 규모 × 5개 자금 상황, 총 90개 조합을 검증합니다. 상세 매출·비용을 바꾸면 제안 현금을 다시 계산합니다. 순현금소진이 없으면 무한한 성공 기간으로 주장하지 않고 해당 입력 상태를 표시합니다.
2. **시작 상태 수정:** 선택한 역할을 유지하고 변경한 단계·팀·자금 구간이 검토 화면에 반영되도록 했습니다. 앞선 Module 3 데이터와 provenance는 유지됩니다.
3. **중단 복원:** 선택·이유·예상 성장률을 브라우저 세션의 선택적 draft로 저장합니다. 화면 이동·새로고침 뒤 복원되며, 자동으로 한 달을 진행하거나 AI에 전송하지 않습니다. 기존 V3에서 같은 세션을 진행한 경우 이전 월의 draft는 안전하게 무시합니다.
4. **선제적 팀 브리핑:** 상태와 기록을 읽어 CFO·Growth·CTO/Customer가 먼저 발언합니다. 투자 제안과 월별 이벤트가 있으면 해당 관점도 추가합니다. 규칙 기반임을 표시하고 로그를 확인할 수 있습니다.
5. **토론 검증:** 프런트와 Worker에서 중복 발언, 자기 자신에게 답하는 발언, 역할 간 상호 응답이 없는 결과를 거절합니다. AI 오류·잘못된 출력은 규칙 기반 토론으로 전환합니다.
6. **3D 로딩 복구:** 다운로드가 끝나기 전에 화면을 전환하면 Babylon이 여러 번 실행되던 오류를 수정했습니다. 로딩 Promise를 공유하고, 느린 다운로드 중 3회 화면 전환에도 런타임이 한 번만 실행되는지 검증합니다.
7. **검증 자료:** 기존 테스트를 보존하면서 초기값·복원·자동 브리핑·지연 로딩·실제 피드백 파일 검증을 추가하고 화면 증거를 갱신했습니다.

실제 월별 상태 변화는 기존 SimulationEngine/DecisionEngine/EventEngine/CalibrationEngine만 계산합니다. 네 엔진, Module3Adapter, handoff bridge 및 연구 페이지는 main 기준 변경이 없습니다. Module 3 점수 산식도 보존됩니다.

## 사용자 흐름

- 전체 여정: 홈 → 시장 → 창업자 자기 점검 → 사업 가정 → Digital Twin → 선택·팀 토론 → 모델 결과 → 실행 계획. 기존 종합 보고서로도 돌아갈 수 있습니다.
- 고민부터: 시장/고객·창업자 질문은 해당 단계로, 가격·투자·시장 진입 질문은 간단한 시작 설정과 관련 결정으로 이동합니다.
- 3분 데모: 샘플 AI 교육 사업 → 개발자/마케터/고객 탐색 선택 → 6개 역할 토론 → 한 달 확정 → 결과·다음 행동 3개.
- 학습: 동일 상태·seed의 다른 선택 비교 → Decision Journal → 7일 행동·30일 실험·측정 지표·재검토 조건.

## 검증 및 배포

최신 실행 결과와 재현 명령은 [VALIDATION.md](VALIDATION.md), 전체 파일 변경 목록과 설계는 [RELEASE.md](RELEASE.md)에 있습니다. Desktop 1440×1000, Mobile 390×844, 한국어/영어 전체 여정, 상태 복원, AI 오류, WebGL 미지원·연결 상실과 저장소 차단을 포함합니다. V3 회귀 테스트는 보존된 `immersive.html` 화면을 원래 경로에 제공하는 fixture로 실행하며 원본 테스트 파일은 수정하지 않습니다.

공개 한국어·영어·Module 4 페이지의 HTTP 200 및 V3 코드가 확인되었습니다. 기존 main의 Pages 배포 작업은 성공 상태입니다. 이 PR의 업로드는 공개 배포가 아닙니다. main 병합과 Pages 배포 성공 확인이 필요하며, Worker는 별도 Cloudflare 배포가 필요합니다.

## 실제로 남은 한계

- LLM 팀은 한 번의 구조화된 요청으로 여섯 관점을 구성합니다. 독립적으로 지속 실행되는 여섯 에이전트 서버나 다중 사용자 실시간 세계가 아닙니다.
- 실서비스 LLM 품질·Worker 배포는 검증하지 못했습니다. 실행 환경의 endpoint OPTIONS 요청은 HTTP 403이었으며, 성공·장애·잘못된 출력 테스트는 통제된 응답으로 진행했습니다.
- 실제 마이크 인식과 전체 스크린리더/WCAG 감사는 미실행입니다. 음성 미지원 시 텍스트 경로는 검증했습니다.
- 아바타는 절차적으로 생성한 스타일화된 캐릭터입니다. 고객 획득은 기존 모델에 있으나 누적 고객 수를 추적하지 않습니다.
- 계정·결제·클라우드 동기화·실시간 시장 검색·외부 분석 서비스는 없습니다. 이는 상용 운영 완성 보고가 아닌 실행 가능한 의사결정 파일럿입니다.
- 30초 이해, 3분 데모, 5분 첫 결정, 재사용 및 지불 의향은 실제 초기 창업자 5–8명의 사용자 테스트로 확인해야 합니다. 기존 SEM/SUS 연구가 새 UX의 효과를 검증하지는 않습니다.
